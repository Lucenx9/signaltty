# ADR-0002 — PTY via `portable-pty`, headless model via `vt100`

- Status: accepted
- Date: 2026-09-28

Context: server needs PTY spawn/resize/kill and a headless screen
model for `pane.read`/reattach snapshots. Candidates: `portable-pty`
(de-facto standard, WezTerm family), `vt100` (small, crates.io, MSRV
1.70), `alacritty_terminal` (fuller, heavier, release-tied, no
stability promise), `wezterm-term` (best mux API but git-only, not on
crates.io, declared unstable), `libghostty-vt` (C/Zig, unstable API,
no renderer).

Decision: `portable-pty` for PTY lifecycle; `vt100` for the Phase 1
headless screen; OSC 9/99/777 extracted by a dedicated byte-stream
scanner independent of the screen parser.

Consequences: publishable builds, minimal deps, attention semantics
never depend on screen-parser fidelity. `alacritty_terminal` is the
documented swap-in behind `TerminalBackend` if `vt100` proves lossy.
