# Native UI refinement verification, 2026-09-29–30

Baseline: `fbe9409469e5f1b12c20d7f627e1674ba2806fd7`; source: `d2de1ef`. Scope:
[spec009](../../specs/009-ui-refinement/spec.md). Verification used the real
GTK/libadwaita/VTE client on KDE Plasma, isolated servers and real PTYs.
Agent output and approval hooks are deterministic fixtures, without paid requests.

## What changed

| Before | After | Why |
|---|---|---|
| Approval text ellipsized beside choices; a long choice forced an 823px minimum pane | Complete question above wrapping native choices; tested at 320px | The decision stays readable in a split |
| Inactive-pane controls stayed invisible under keyboard focus | Immediate reveal and inset focus outline | Keyboard users can see the control they operate |
| Close replaced the workspace status | Independent reserved target beside persistent urgency | Closing and triaging no longer compete for one slot |
| Very faint metadata, animated status/focus paint | Clearer hierarchy, instant focus/state styling | Frequent navigation stays calm |
| Press scaling survived disabled animation interpolation | Explicit active-state reduced-motion override | Desktop preferences remove static transforms too |

The implementation retains system fonts, semantic Adwaita colors, existing
attention/decision IDs and mounted terminals. Native tab-view interaction remains
toolkit-owned; the custom content Stack no longer crossfades during navigation.


The helper uses temporary GTK configuration and disables portal font overrides for the font scene;
it does not change the desktop's preferences.

## Behavioral proof and gates

[Validation](evidence-ui-2026-09-29/validation.json) records 188 workspace tests
and 10 separate graphical tests, all passing. Build, fmt and Clippy pass;
the two existing server warnings remain untouched.
[Graphical results](evidence-ui-2026-09-29/display-tests.jsonl) cover actual 320px
allocation, complete labels, original answer IDs and VTE identity; rendered
inactive-pane control pixels; launch/runtime motion preferences; and native
render transforms under pointer, reduced-motion and keyboard activation.

The approval and focus tests first failed against the original behavior. The
motion test also failed with the initial, insufficient-specificity override,
then passed with the final CSS. It observes rendered transforms, not CSS strings.

[Reliability](evidence-ui-2026-09-29/reliability.jsonl) passes single-window
activation, preserved approval/answer, reconnect output, responsive GTK during
server stall, split/close and restored exited status.
[Refresh measurement](evidence-ui-2026-09-29/refresh.jsonl) passes 400 hooks across
eight workspaces: 34 workspace reads for the 200-message burst, no full list refresh.

Standards and Spec reviews pass. Motion review approves after the specificity
correction. Clipboard, IME, desktop notification clicks and live paid providers
retain the separate coverage limits documented in the verification feature map.
