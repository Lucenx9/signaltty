Base revision: `84d0307`. Reviewers: Grok 4.7 on T3's direct xAI provider
`grok`, and Claude Sonnet 5.5 on `claudeAgent`. OpenRouter was not used.
The review follows docs/14: herdr for agent state, cmux for attention and

diagnosing-bugs, ask-matt, apple-design, emil-design-eng, frontend-design,
spec-kit, verify-signaltty and pr. No new motion or color tokens were needed.

## Palette corrections

| Before | After | Why |
| --- | --- | --- |
| Keyboard selection leaves the visible list. | Native adjustment reveals the selected row while search keeps focus. | Users must see the target that Enter will activate. |
| Filtering after scrolling hides the first match. | Filtering resets the adjustment to the first result. | The row-selected signal sees geometry from before GTK's next layout. |
| No-match search leaves blank space. | A native status page explains how to recover; clearing restores results. | Empty feedback makes the next action clear. |
| Commands repeat “Command” without their shortcut. | Existing accelerators appear in GTK-formatted subtitles and accessible descriptions. | Teach repeated keyboard workflows without adding actions. |
| Shortcut suffixes truncate even “New Workspace” at Sans 18 and 360px. | Full-width titles sit above shortcut subtitles. | Text enlargement must preserve short command names. |

The final implementation preserves native ActionRow controls, literal titles,
target IDs, activation callbacks and terminal focus restoration. Long workspace
names and paths keep two-line bounds and full-text tooltips. Keyboard users
still see ellipsized long paths; a full selected-result detail view would be a
separate design change. No claim of complete keyboard access to those tooltips.

## Reproduction and verification

Each display test runs in its own Xvfb display and D-Bus session:

```sh
GTK_A11Y=none xvfb-run -a dbus-run-session -- cargo test -p signaltty-gui app::tests::palette_keyboard_selection_stays_visible_while_search_keeps_focus -- --exact --ignored --test-threads=1
GTK_A11Y=none xvfb-run -a dbus-run-session -- cargo test -p signaltty-gui app::tests::palette_empty_results_and_shortcuts_fit_narrow_appearances -- --exact --ignored --test-threads=1
scripts/verify.sh full
```

The first regression failed before the scroll correction with row 30 at
`y=1650`, height 55, viewport 375. The minimal eight-workspace case failed
with row 7 at `y=385`. After the first fix, the additional filter regression
failed with the first match at `y=-193`; resetting the filter adjustment fixes
that path. The empty-feedback test failed with “empty search needs explicit
feedback”. The large-text regression then caught a shortcut suffix truncating
a short command name. All these assertions exercise production widgets.

Tests cover rapid Down/Up, first/last boundaries, search focus, filtered
selection, immediate Enter activation, a mapped empty status page, no-op Enter
without matches, recovery, literal long names and 360px bounds. Native light,
dark and Sans 18 renders are inspected. The application's production CSS and
high-contrast class are loaded in the enlarged-text scene.

Screen-reader reading order, live announcement, real desktop high-contrast
themes, IME and on-screen keyboard input were not run. The class-based scene
is a presentation regression, not certification of those workflows.

Selected native evidence is retained in
[2026-10-08-palette-quality](2026-10-08-palette-quality/): light/dark palette,
row 30 selected, a readable large-text shortcut and dark empty-state feedback.
These renders come from the full runner's isolated GTK processes.

The full gate also exposed a pre-existing sidebar test assumption. With Cairo
and a 630px logical window, the responsive sidebar was collapsed and its resize
handle was not mapped. The test attempted focus before opening it. The isolated
Cairo command reproduced the failure; the test now explicitly shows the sidebar
and waits for the handle to map before requesting focus. Application behavior
is unchanged, and the temporary diagnostic was removed. The worker-chip test
then exposed the shared environment cause: this distribution defaults Xvfb to
640×480 pixels. A probe confirmed scale factor 1, and the test passed with an
explicit 1600×1200 screen. The full runner now supplies that screen size for
all isolated GTK tests and the refresh benchmark, preserving all assertions.

## Broader audit candidates

Grok reviewed sidebar, header, pane controls, board, worktrees and diff
presentation. The following observations are retained for separate focused
reproduction and specifications. They are not fixed by this palette patch.
Code inspection alone does not establish the proposed UX change as correct.

| Before | Proposed after | Evidence and disposition |
| --- | --- | --- |
| Shell header can show a dangling slash with no agent context. | Show useful branch/path context and hide an empty separator. | Observed in initial native renders; app.rs binds separator visibility to the workspace mark. Needs a header layout regression and a decision on agent versus filesystem context. |
| Enabled worktree Remove uses the same flat treatment as unavailable removal. | Clarify availability and explain disabled reasons. | Observed in worktree renders and workspace_dialogs.rs. Native flat buttons still have hover/disabled states; this is a clarity candidate, not proof that the action is unreachable. |
| Change counts use signed plain text. | Consider semantic added/removed text and explicit accessible wording. | Observed in diff renders. Existing signs already convey the distinction without color; color is a scanability suggestion. |
| Several titles, finished rows and chips remain muted in high contrast. | Verify required text and remove muting where contrast is insufficient. | CSS inspection; no measured contrast violation or actual desktop HC reproduction in this audit. |
| Needs you is the second board column in narrow windows. | Consider initially revealing pending decisions. | Board order and width from source. Requires attention-first acceptance criteria; changing column order is not part of palette correction. |
| Board refresh closes and recreates its dialog. | Preserve column scroll and focused card across refresh. | app.rs source observation; reproduce with live task updates before choosing an in-place reconcile or state restoration. |
| Done counts all tasks but displays at most 20 cards. | Make the visible subset explicit. | board.rs source observation. Needs a native over-20-card fixture. |
| Pane headers reserve action space and conditionally ellipsize titles. | Verify that approval badges remain within narrow pane bounds. | terminal.rs/CSS inspection. Existing worker-chip tests constrain this layout; test the claimed short-title plus approval combination before changing it. |
| Sidebar resize focus uses a subtle wash. | Consider a stronger inset keyboard outline. | CSS inspection. Requires an actual keyboard-focus render in both themes. |
| Pane-less board cards do not activate. | Explain the unavailable destination and verify accessible names. | board.rs inspection. Requires accessibility observation, not an assumption that child labels are unnamed. |

Sonnet's final palette review reports no code blockers. Its earlier findings
on filter geometry, empty-state visibility assertions and shortcut compression
were reproduced and corrected. The broader candidates above remain explicitly
outside the delivered patch.
