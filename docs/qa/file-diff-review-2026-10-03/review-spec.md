## Spec-axis findings

1. **Read-only contract is breached by repository clean filters.** The spec says “The feature MUST remain read-only and MUST NOT alter Git state, workspace state, running agents, or terminal widgets” ([spec.md:64](/home/simone/code/signaltty/specs/014-file-diff-review/spec.md:64)). The new tracked-file route invokes `git diff` ([file_diff.rs:124](/home/simone/code/signaltty/crates/signaltty-server/src/file_diff.rs:124)), which runs configured clean filters while comparing worktree content. The integration test itself configures `filter.slow.clean = sh slow.sh`; that script writes `filter.pid` and `sleeper.pid`, and the test waits for those workspace files ([file_diff.rs:495](/home/simone/code/signaltty/crates/signaltty-server/tests/file_diff.rs:495), [file_diff.rs:518](/home/simone/code/signaltty/crates/signaltty-server/tests/file_diff.rs:518)). A selected-file read can therefore mutate the checkout through Git configuration. Either prevent side-effectful filters on this path or clarify the trust/exception in the spec and ADR. This is a real contract tension with Git-normalized comparisons, so the remedy needs a deliberate choice.

2. **The incomplete-preview notice names the wrong limit.** The spec requires that “truncation MUST be visible” ([spec.md:61](/home/simone/code/signaltty/specs/014-file-diff-review/spec.md:61)); the contract sets both a 512 KiB byte limit and a 10,000-line limit ([ipc.md:17](/home/simone/code/signaltty/specs/014-file-diff-review/contracts/ipc.md:17)). The core sets `truncated = true` when it reaches the line limit ([diff.rs:127](/home/simone/code/signaltty/crates/signaltty-core/src/diff.rs:127), [diff.rs:214](/home/simone/code/signaltty/crates/signaltty-core/src/diff.rs:214)), yet the GUI always states “Incomplete preview: size limit reached” ([changes.rs:464](/home/simone/code/signaltty/crates/signaltty-gui/src/changes.rs:464)). The GUI test models 10,001 lines and asserts that incorrect size explanation ([app_tests.rs:1441](/home/simone/code/signaltty/crates/signaltty-gui/src/app_tests.rs:1441)). A generic “Incomplete preview” or the core notice would be accurate.

No other missing requirement or scope expansion was confirmed. In particular, a newly staged empty file returns a header-only `text` result with a notice, rather than being mislabeled `unchanged`.

## Resolution recheck

Both findings are resolved against the revised contract. `FR-009` now explicitly limits signaltty's read-only promise to its own edit/stage actions, Store state, agents, and terminals, while allowing trusted Git clean/process conversions ([spec.md:64](/home/simone/code/signaltty/specs/014-file-diff-review/spec.md:64), [spec.md:86](/home/simone/code/signaltty/specs/014-file-diff-review/spec.md:86)). The plan, IPC contract, ADR, and IPC documentation state the same boundary. The timeout fixture still proves configured filters execute and are bounded; its PID markers now go to `TestServer.integration_home`, outside the checkout ([file_diff.rs:524](/home/simone/code/signaltty/crates/signaltty-server/tests/file_diff.rs:524)). This resolves the previously reported spec conflict under the clarified trust model.

For truncated text, the GUI now displays the core's specific notice when supplied and uses “size or line limit” only as a fallback ([changes.rs:462](/home/simone/code/signaltty/crates/signaltty-gui/src/changes.rs:462)). That matches the 10,000-line and 512 KiB contract. The revised GUI fixture supplies the line-limit notice. No open spec-axis finding remains from this review.
